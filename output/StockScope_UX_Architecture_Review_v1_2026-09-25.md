# StockScope 제품 UX 설계안

정보 구조와 사용자 흐름 검토 · 버전 1.0 · 2026년 9월 25일

StockScope의 각 화면은 현재 상태, 판단 이유, 다음 행동을 순서대로 전달해야 한다. 발견·신규 진입 분석·실제 보유 관리를 구분하고, 데이터 준비와 부족 상태에서도 사용자가 이어갈 수 있는 행동을 제공한다. 이번 문서는 사람과 설계자가 함께 검토할 제품 구조와 와이어프레임을 제안한다.

이번 설계는 요청문에 제시된 사용 문제를 대상으로 한다. 소스 비교와 개발 작업 명세 전환은 다음 단계다. Strategy·Scanner·Ranking·Risk, Holding 원장과 손익, Applied Management Plan, Market Store, NEWS Provider 연결 구조와 계산 의미는 변경 대상에 포함하지 않는다. 화면에 필요한 상태값의 존재 여부는 구현 검토 때 확인한다.

## A 전체 UX 진단

| 구조적 문제 | 사용자가 겪는 혼란 | 설계 방향 |
| --- | --- | --- |
| 작업 시작과 결과 사이의 연결이 끊김 | 데이터 준비를 눌러도 진행 여부와 다음 행동을 알 수 없음 | 시작 즉시 진행 화면으로 연결하고 상태·완료·복귀를 같은 흐름으로 구성 |
| 화면 역할과 보유 상태가 섞임 | 보유 중인데 신규 진입 판단이 관리 지시처럼 보임 | 분석의 관점을 명시하고 실제 보유 관리는 내 종목 관리로 연결 |
| 정보 중요도가 구분되지 않음 | 긴 설명과 뉴스 때문에 분석 결론을 찾기 어려움 | 결론·핵심 이유·행동을 먼저 배치하고 부연 설명의 우선순위를 낮춤 |
| 데이터 부족 안내가 끝점이 됨 | 왜 부족한지, 준비하면 해결되는지 모름 | 현재 확보량·필요량·부족 이유·해결 경로를 필요한 만큼 표시 |
| 관심과 보유를 같은 구조로 취급 | 관찰할 조건과 실제 수량·손익을 구분하기 어려움 | 관심은 판단 변화, 보유는 자산 상태와 적용된 관리 기준을 우선 |
| 상태 표시가 시스템 이름 중심임 | 어떤 기능을 쓸 수 있는지보다 provider 명칭을 먼저 보게 됨 | 전역에는 사용 영향 요약 하나, 상세에는 provider별 상태 표시 |
| 과거 성과의 사용 목적이 불분명함 | 매번 실행해야 하는지, 현재 판단과 무엇이 다른지 모름 | 분석을 검토하는 선택적 검증 도구로 정의하고 재사용 결과를 먼저 표시 |
| 정렬과 그래프의 정보 기준이 약함 | 화면의 흐름과 시장 변화를 빠르게 읽기 어려움 | 콘텐츠 폭을 통일하고 미니 차트에 기간·기준·실제 관측값을 표시 |

### 모든 화면에 적용할 판단 기준

“이 정보가 없으면 사용자가 다음 행동을 결정하기 어려운가?”를 기준으로 기본 노출 여부를 정한다. 영향이 큰 데이터 기준일·실제 보유 상태·작업 실패·분석 관점은 숨기지 않는다. 긴 계산 설명과 보조 지표는 펼쳐보기로 이동한다. 기사는 원문 링크로 열며 내부 본문 펼쳐보기를 만들지 않는다.

요청한 12가지 문제는 모두 포함한다. 데이터 준비는 D8·F, 시장 정렬과 그래프는 D1, provider는 D7, 긴 설명은 G, 뉴스와 보유 관점은 D3, 과거 성과와 3년 부족은 D4·F, 성과 추적의 범위는 B, 보유 관리 기준과 관심·보유 구분은 D5·D6·E에서 다룬다.

## B 전체 정보 구조

상위 메뉴는 사용자의 작업 목적에 맞춰 현재 여섯 화면을 유지한다. 데이터 준비와 시스템 상태는 주식 판단 화면과 경쟁하는 메뉴 대신 모든 화면에서 접근하는 공통 도구로 둔다.

| 메뉴 | 답하는 질문 | 담당 범위와 경계 |
| --- | --- | --- |
| 시장 현황 | 현재 시장을 어떻게 보고 있는가 | 시장 상태와 흐름, 자료 기준일, 후보 찾기로 이동. 개별 종목 매수·매도 지시 제외 |
| 종목 후보 찾기 | 어떤 종목부터 검토할 것인가 | 기존 Scanner 결과의 발견과 비교. 실제 보유 관리와 확정 매수 추천 제외 |
| 종목 분석 | 이 종목을 새로 검토할 때 무엇을 볼 것인가 | 신규 진입 관점, 가격 계획, 근거, 기업 정보. 실제 보유분의 매도 판단과 원장 수정 제외 |
| 종목 과거 성과 | 같은 분석 조건이 과거에는 어떻게 작동했는가 | 조건·기간별 기존 검증 결과와 실행. 일상 분석의 필수 선행 절차가 아님 |
| 종목 성과 추적 | 분석 이후 결과는 어떻게 이어졌는가 | 현 기능과 진입점을 유지. 이번 작업에서는 메뉴 의미·복귀·공통 상태만 점검 |
| 내 종목 관리 | 관찰하거나 보유한 종목을 어떻게 확인할 것인가 | 관심과 보유를 분리. 실제 원장·손익·적용된 보유 기준을 기준으로 표시 |

### 메뉴 간 이동 관계

```text
[시장 현황] -> [종목 후보 찾기] -> [종목 분석]
                                     |
                         +-----------+-----------+
                         |                       |
                   [관심 등록]             [보유 등록]
                         |                 실제 거래 입력
                         v                       v
                [내 종목 - 관심] ------> [내 종목 - 보유]
                         |                       |
                         +--> [종목 분석] <-------+
                                |
                          [종목 과거 성과]
                                |
                          [분석으로 복귀]

모든 화면 -> [데이터 상태] -> [상세 상태 / 데이터 준비]
데이터 부족 -> [데이터 준비 진행] -> [출발 화면으로 복귀]
```

시장부터 순서대로 이동하는 경로는 기본 안내다. 이미 종목을 아는 사용자는 종목 분석이나 내 종목 관리로 직접 들어갈 수 있다. 모든 단계를 필수 절차로 만들지 않는다.

화면 간에는 선택 종목, 시장 구분, 출발 화면과 당시 필터·스크롤 위치를 유지하는 경험을 목표로 한다. 복귀 시 자동으로 재분석하거나 수집을 다시 시작하지 않는다. 현재 데이터와 이전 결과가 다르면 기준 시각을 알려주고 명시적인 갱신 행동을 제공한다.

전역 상단에는 “데이터 상태” 진입점 하나와 필요한 경우 “데이터 준비 중” 작업 상태를 둔다. 공급자 이름 네 개를 상단에 상시 나열하지 않는다. 모바일에서는 같은 항목을 탐색 메뉴 안과 화면 상단 작업 표시에서 접근할 수 있게 한다.

## C 사용자 핵심 흐름

### 처음 사용하거나 데이터가 부족한 경우

시장 현황에서 사용 가능한 범위와 부족한 범위를 확인한다. “시장 데이터 준비”를 누르면 준비 범위 확인 후 시작하며 즉시 진행 화면으로 이동한다. 완료 화면에는 “종목 후보 찾기” 또는 출발 화면의 목적에 맞는 다음 행동을 제공한다. 준비되지 않은 상태에서 Scanner를 실행해 같은 오류를 반복하게 만들지 않는다.

### 후보를 발견해 관심 종목으로 등록하는 경우

시장 현황 → 종목 후보 찾기 → 후보 행 선택 → 종목 분석 → 관심 등록 → 내 종목의 관심 목록으로 이어진다. 후보의 선정 이유와 분석의 신규 진입 관점을 이어서 보여준다. 관심 등록은 원장에 거래를 만드는 행동이 아니다. 등록 후에는 “관심 목록에서 확인”을 제공하고 분석 화면도 계속 볼 수 있게 한다.

### 관심 종목을 다시 확인하는 경우

관심 목록에서 현재 판단, 관심 가격이 있다면 현재가와의 관계, 마지막 분석 시각을 확인한다. “분석 보기”로 최신 상태를 검토한다. 변화 기록이 실제로 있으면 이전 대비 차이를 보여주고, 없으면 “변화 없음”을 만들어 표시하지 않는다. 과거 성과는 사용자가 판단을 더 검토하고 싶을 때 선택한다.

### 실제 매수한 종목을 등록하는 경우

관심 또는 종목 분석 → “보유 등록” → 기존 거래 입력 절차 → 저장 결과 확인 → 내 종목의 보유 상세로 이동한다. 실제 수량·평균단가는 거래 원장의 값이다. 분석 화면의 가상 수량·가상 평균단가를 실제 거래로 자동 전환하지 않는다. 보유 등록이라는 이름을 실제 주문으로 오인하지 않도록 입력 화면에서 기록 목적을 명시한다.

### 이미 보유한 종목을 분석하는 경우

보유 상세 → “신규 진입 관점으로 분석” → 종목 분석으로 이동한다. 상단에 실제 보유 상태와 분석 관점을 함께 표시한다. 신규 진입 조건이 맞지 않더라도 현재 보유분을 매도하라는 안내로 바꾸지 않는다. “보유 관리로 돌아가기”를 통해 적용된 손절·목표 기준과 실제 원장을 다시 확인한다.

### 과거 검증 중 자료가 부족한 경우

종목 분석 → 종목 과거 성과 → 기존 결과 확인 또는 새 검증 요청 → 자료 충족 여부 확인으로 이어진다. 부족 원인이 수집 누락이면 기존 데이터 준비로 연결한다. 상장 기간 자체가 짧으면 준비로 해결할 수 없다고 설명하고, 현재 기능이 지원하는 경우에만 가능한 기간을 선택하게 한다. 준비 완료 후 원래 종목과 검증 조건으로 돌아온다.

### 흐름 전반의 상태 구분

한 종목이 관심과 보유 상태를 동시에 가질 수 있는지는 기존 기능의 의미를 따른다. 보유 등록 후 관심 상태를 자동 삭제하지 않는다. 뉴스 오류, 일부 provider 오류, 과거 검증 미실행은 정상적인 관심 등록이나 기존 보유 확인을 불필요하게 막지 않는다. 다만 실행에 필요한 데이터가 실제로 없으면 행동 제한 이유와 해결 경로를 같은 위치에서 제공한다.

## D1 시장 현황

### 현재 문제

시장 설명과 일부 요소의 가로폭이 달라 정렬이 깨진다. Sparkline은 기간과 기준이 불명확하고, 데이터 준비를 시작한 뒤 현재 작업 상태를 알기 어렵다.

### 사용자가 혼란스러운 이유

같은 수준의 정보인지 구분하기 어렵고, 선의 기울기만으로 실제 변화량이나 최신 여부를 판단해야 한다. 데이터가 부족한 상태와 시장 자체가 불안정한 상태도 섞여 보일 수 있다.

### 개선 원칙

시장 결론과 데이터 상태를 분리한다. 데스크톱은 최대 콘텐츠 폭 1,200px, 좌우 여백 24px를 초기 기준으로 삼고 제목·설명·배너·차트를 같은 정렬선에 맞춘다. 좁은 화면은 여백 16px와 단일 열을 사용한다. Dark와 Low-Glare Light에서 정보 계층을 동일하게 유지한다.

### 권장 정보 순서

시장 상태와 기준일 → 핵심 이유 최대 2개 → KOSPI·KOSDAQ 흐름 → 시장 폭·거래 정보 → 후보 찾기 → 보조 설명 순으로 둔다. 시장 판단 값은 기존 계산의 의미를 그대로 표현한다.

### 권장 인터랙션

- 미니 차트에 표시 기간, 첫값·마지막값, 구간 내 최고·최저 관측값, 기준선을 제공한다. 고저점은 제공된 시계열에서 확인된 값만 쓴다.
- 지수값 차트는 첫 관측값 기준선을, 등락률 차트는 0% 기준선을 사용한다. 서로 다른 단위를 혼합하지 않는다.
- 포인터·키보드 초점 또는 터치로 날짜와 값을 확인한다. 누락 구간은 선으로 연결하지 않는다. 색 외에도 수치와 방향 표기를 제공한다.
- 준비 시작은 D8로 즉시 연결한다. 정상 상태의 주요 다음 행동은 “종목 후보 찾기”다.

### 간단한 와이어프레임

```text
시장 현황                         데이터 상태   데이터 준비
------------------------------------------------------------
현재 시장 판단                     데이터 기준  {날짜}
핵심 이유 1 / 핵심 이유 2

KOSPI                     KOSDAQ
{현재 지수} {등락률}        {현재 지수} {등락률}
고점       /\             고점      __
기준 -----/--\___         기준 ----/--\---
저점 _/          끝값      저점 __/      \_ 끝값
{시작일}        {종료일}    {시작일}       {종료일}
------------------------------------------------------------
상승/하락 종목 수      거래 변화      필요한 시장 지표

[종목 후보 찾기]                   [판단 기준 자세히]
```

차트의 모양과 값은 구조 예시다. 실제 지수 움직임이나 장중 고저점을 뜻하지 않는다. 보조 설명 하나만 전체 콘텐츠 폭을 벗어나지 않도록 같은 컨테이너 기준을 적용한다.

## D2 종목 후보 찾기

### 현재 문제

발견 단계의 후보 결과가 확정적인 투자 판단처럼 읽힐 수 있다. 준비가 필요한 경우 실행 전후의 안내와 데이터 준비 경로가 끊겨 있다.

### 사용자가 혼란스러운 이유

후보 순위, 선정 이유, 개별 종목의 최종 검토가 같은 결정처럼 보인다. 실행에 필요한 자료가 없을 때 사용자는 조건을 바꿔야 하는지 기다려야 하는지 알기 어렵다.

### 개선 원칙

이 화면의 역할을 “먼저 검토할 종목 발견”으로 고정한다. 기존 Scanner·Ranking 결과를 해석 가능한 목록으로 표현한다. 조건 선택과 결과 비교를 구분하고 기본 행동을 종목 분석으로 연결한다.

### 권장 정보 순서

현재 탐색 조건 → 데이터 준비 여부와 결과 기준일 → 실행 상태 → 후보 수와 결과 목록 → 선택 종목의 선정 이유 → 종목 분석 순으로 배치한다. 모든 전략의 긴 설명을 실행 버튼 위에 나열하지 않는다.

### 권장 인터랙션

- 결과는 정렬 가능한 표를 우선 사용한다. 기본 순서는 기존 Ranking이며 임의로 새 순위를 계산하지 않는다.
- 종목명이나 행 선택으로 분석 이동 대상을 명확히 한다. 주요 행동은 “종목 분석”, 관심 등록은 보조 행동으로 둔다.
- 조건을 바꾸면 이전 결과를 유지하되 “이전 조건의 결과”를 표시한다. 새 조건의 결과인 것처럼 보여주지 않는다.
- 자료 부족은 실행 영역 가까이에 이유와 “데이터 준비”를 함께 둔다. 재방문 시 기존 조건과 결과를 보존하고 자동 재실행하지 않는다.

### 간단한 와이어프레임

```text
종목 후보 찾기                         데이터 기준 {날짜}
현재 조건에서 먼저 검토할 종목을 찾습니다
------------------------------------------------------------
시장 {선택}   기존 탐색 조건 {요약}        [조건 변경]
데이터 {준비 상태}                        [후보 찾기]

{결과 수}개 후보                         실행 {시각}
------------------------------------------------------------
종목       현재 가격     기존 평가     선정 이유
A종목      {값}          {값}          {핵심 이유}
B종목      {값}          {값}          {핵심 이유}
C종목      {값}          {값}          {핵심 이유}
------------------------------------------------------------
선택  A종목
먼저 검토할 이유 {한 문장}
[종목 분석]     [관심 등록]
```

후보가 없는 경우에는 “현재 조건에 해당하는 후보가 없습니다”와 조건 확인·수정 행동을 제공한다. 이를 시스템 오류나 시장 전체 매수 금지로 표현하지 않는다.

## D3 종목 분석

### 현재 문제

뉴스가 긴 영역을 차지해 분석의 중심이 흐려진다. 실제 보유 종목에도 신규 진입 판단이 크게 표시돼 보유 관리 지시와 혼동된다. 긴 설명 때문에 결론과 다음 행동이 늦게 보인다.

### 사용자가 혼란스러운 이유

같은 종목이라는 이유로 신규 매수 검토와 기존 보유분 관리가 같은 판단이라고 받아들이기 쉽다. 뉴스가 제공하는 기능 수준도 기사 연결과 투자 해석 사이에서 불분명하다.

### 개선 원칙

분석의 관점을 상단에서 명시하고 결론·가격 계획을 우선한다. 보유 상태는 실제 원장 기준으로 표시하되 신규 진입 계산을 보유 매도 판단으로 바꾸지 않는다. 뉴스는 보조 정보로 배치하고 NEWS.1에서 없는 해석을 생성하지 않는다.

### 권장 정보 순서

종목과 분석 기준일 → 실제 관심·보유 상태 → 신규 진입 관점 결론과 핵심 이유 → 다음 행동 → 가격 계획과 차트 → 판단 근거·기술적 상태 → 기업 분석 → 최근 뉴스 → 부가 분석과 과거 성과 진입점 순으로 둔다.

### 권장 인터랙션

- 보유 종목에는 “신규 진입 관점”과 “보유 관리 보기”를 표시한다. “보유 등록”은 미보유 종목에만 제공한다.
- NO_TRADE의 화면 표현은 기존 의미에 맞는 “신규 진입 보류”다. 자동 매도나 보유분 청산으로 해석하지 않는다.
- 뉴스는 기본 3건, 각 제목·출처·시각과 설명 최대 1줄을 제안한다. “뉴스 더 보기”는 최대 10건의 목록을 늘리는 행동이며 본문을 펼치지 않는다. 제목은 새 탭 원문 링크다.
- NEWS.2는 지원되는 관련성 설명 한 줄을 추가할 수 있게 한다. 기업·업종·정책·공급망 연결을 설명하며 긍정·부정 투자 판단은 만들지 않는다.

### 간단한 와이어프레임

```text
A종목 {코드}                        분석 기준 {시각}
보유 중  {실제 수량}주                 [보유 관리 보기]
------------------------------------------------------------
신규 진입 관점  {기존 판단}
핵심 이유 {한두 문장}
[관심 등록/해제] [과거 성과 확인]
------------------------------------------------------------
가격 계획 {기준값}                 가격 차트
판단 근거                          [세부 지표]
기업 분석 {요약}                    [기업 정보 상세]
------------------------------------------------------------
최근 뉴스                                        [새로고침]
제목 1 > 원문      출처 / 시각       설명 한 줄
제목 2 > 원문      출처 / 시각       설명 한 줄
제목 3 > 원문      출처 / 시각       설명 한 줄
[뉴스 더 보기]
```

기존 가상 보유 입력은 “가상 조건”으로 명시하고 실제 수량·평균단가와 별도 영역에 둔다. 실제 원장을 바꾸는 입력처럼 배치하지 않는다.

## D4 종목 과거 성과

### 현재 문제

기능을 실행해야 하는 이유와 빈도가 불분명하다. “3년 검증 데이터 부족”만 표시되면 사용자가 해결할 행동을 찾기 어렵다.

### 사용자가 혼란스러운 이유

과거 검증이 신규 진입 판단의 필수 단계인지, 결과가 없으면 분석도 무효인지 구분되지 않는다. 데이터 수집 누락과 종목 자체의 짧은 상장 기간을 같은 부족 메시지로 보게 된다.

### 개선 원칙

이 화면은 “현재 검토 중인 조건이 과거에는 어떻게 작동했는가”에 답하는 선택적 검증 화면이다. 동일 조건의 기존 결과가 있으면 먼저 보여준다. 재계산 필요 여부는 기존 결과와 데이터의 기준 차이로 설명한다.

### 권장 정보 순서

종목·검증할 질문 → 기존 결과와 실행 시각 → 전략·기간·조건 → 데이터 충족 상태 → 결과 요약·실패 사례·가격 흐름 → 상세 통계 순으로 둔다. 결과의 수익률만 크게 강조하지 않고 해당 조건과 검증 범위를 함께 표시한다.

### 권장 인터랙션

- 기존 저장 결과를 지원하면 같은 종목·전략·기간·조건의 결과를 재사용한다. 사용자는 최초 실행, 조건 변경, 최신 자료 반영을 원할 때 실행한다. 재방문만으로 재계산하지 않는다.
- 자료 부족 시 현재 기간·유효 거래일 수·현재 검증이 요구하는 수를 표시한다. 필요 수는 기존 검증 기준을 읽으며 UX에서 새 숫자를 정하지 않는다.
- 미수집이면 “부족한 데이터 준비”로 연결한다. 종목 단위 준비를 현재 기능이 지원하지 않으면 실제 지원 범위를 알려준다.
- 상장 기간 부족이면 수집으로 해결된다고 안내하지 않는다. 기존 계산이 짧은 기간을 허용할 때만 기간 변경을 제공하며 결과를 “3년 검증”으로 부르지 않는다.

### 간단한 와이어프레임

```text
A종목 과거 성과                         [종목 분석으로]
선택한 조건의 과거 결과를 확인합니다
------------------------------------------------------------
전략 {기존 전략}   기간 {선택}   조건 {요약}
기존 결과 {있음/없음}          실행 {시각}

데이터 준비가 필요합니다
확보 {N}개 / 필요 {M}개 유효 거래일
확보 기간 {시작일~종료일}
이유 {미수집 / 상장 기간 / 품질 등 실제 원인}
[부족한 데이터 준비]            [분석으로 돌아가기]
------------------------------------------------------------
결과가 있을 때
{핵심 결과}    {해석 범위}    {주의할 결과}
기간별 흐름 / 기존 제공 통계
[검증 조건과 계산 설명]
```

자동 재사용은 기존 저장·조회 기능이 있는 범위의 UX 제안이다. 새로운 캐시·DB·계산 기능이 필요하면 이번 단계에서 구현 범위로 확정하지 않는다.

## D5 내 종목 관리의 관심 종목

### 현재 문제

관심 종목과 보유 종목의 화면 구조가 유사해 관찰의 목적이 드러나지 않는다. 보유 손익 중심의 정보는 아직 매수하지 않은 사용자에게 우선순위가 낮다.

### 사용자가 혼란스러운 이유

관심 등록이 거래 기록처럼 보이거나, 다음에 어떤 조건을 확인해야 하는지 알기 어렵다. 최신 분석과 등록 시점의 분석이 구분되지 않으면 상태 변화도 오해하기 쉽다.

### 개선 원칙

관심 화면은 “매수를 검토하며 관찰할 종목”을 관리한다. 현재 판단과 관찰 조건, 마지막 확인 시각을 중심으로 구성한다. 실제 보유 수량·손익은 기본 열에서 제외하고 보유 상태가 함께 있으면 보유 화면 링크만 제공한다.

### 권장 정보 순서

관심 종목 수와 기준일 → 종목별 현재 판단 → 관심 가격과 현재가 관계가 있다면 표시 → 조건 변화가 확인되면 표시 → 마지막 분석 → 분석 보기·보유 등록 → 관련 뉴스 순으로 둔다.

### 권장 인터랙션

- 목록은 종목, 현재 가격, 현재 판단, 마지막 분석을 기본 열로 둔다. 관심 가격·변화 정보는 실제 저장값과 비교 기능이 있는 경우에만 추가한다.
- 행 선택은 관심 상세로 연결하고 주요 행동은 “분석 보기”다. 보유 등록은 기존 거래 입력을 거쳐야 한다.
- 관심 해제는 실제 거래나 보유 기록 삭제와 다른 행동임을 명확히 한다. 보유 중인 종목의 관심을 해제해도 원장을 변경하지 않는다.
- 뉴스는 선택한 종목 상세의 하단에 소수만 배치한다. 목록 모든 행에 뉴스 카드나 긴 설명을 붙이지 않는다.

### 간단한 와이어프레임

```text
내 종목 관리
[관심 종목 {N}]   보유 종목 {M}
------------------------------------------------------------
종목       현재 가격    현재 판단       마지막 분석
A종목      {값}         {기존 판단}      {시각}
B종목      {값}         {기존 판단}      {시각}
------------------------------------------------------------
A종목
현재 판단 {한 줄}                     데이터 {기준일}
관찰할 조건 {기존 값이 있을 때}
관심 가격 {있는 경우} / 변화 {검증된 비교가 있을 때}
[분석 보기]  [보유 등록]  [관심 해제]

최근 뉴스  {제목과 원문 링크 중심}
```

관심 가격·조건 변화가 현재 제공되지 않는다면 빈 카드나 임의 기본값을 만들지 않는다. 해당 정보가 없어도 현재 판단과 최근 분석으로 완성된 관심 목록을 구성한다. 새 저장 필드 도입 여부는 후속 별도 검토 사항이다.

## D6 내 종목 관리의 보유 종목

### 현재 문제

관심 목록과 비슷한 구조 때문에 실제 수량·평균단가·손익·관리 기준의 우선순위가 약하다. “현재 관리 계획”이라는 이름과 선택형 UI가 실제 적용 상태를 충분히 설명하지 못한다.

### 사용자가 혼란스러운 이유

무엇에 적용된 계획인지, 이미 적용된 기준인지, 새 분석 제안인지 구분하기 어렵다. 계획 하나만 있는데 선택 목록이 있으면 선택하지 않은 다른 대안이 있다고 오해한다.

### 개선 원칙

화면의 기준은 실제 보유 Position과 원장이다. 명칭은 “보유분 관리 기준”을 권장한다. 현재 적용된 손절·목표와 적용 기준일을 보여주고 신규 진입 관점은 보조 이동으로 둔다. 계산·적용 절차와 손익 의미는 그대로 유지한다.

### 권장 정보 순서

보유 목록 → 선택 종목의 수량·평균단가 → 최근 확정 가격과 기준일 → 평가손익·실현손익 → 현재 관리 상태 → 보유분 관리 기준 → 거래 기록 → 관련 분석과 뉴스 순으로 둔다.

### 권장 인터랙션

- 적용된 기준 하나는 단일 기준표로 표시한다. 선택형 드롭다운이나 여러 계획 비교를 기본 UI로 만들지 않는다.
- “손절 기준, 1차 목표, 2차 목표, 적용 기준일, 현재 상태”는 실제 값만 표시한다. 없으면 “적용된 관리 기준이 없습니다”와 현재 지원되는 다음 행동을 제공한다.
- 새 분석이 있어도 적용 기준을 자동 교체하지 않는다. 기존 적용 기능이 있으면 변경 전후 기준을 확인한 뒤 그 기능으로 연결한다.
- 거래 추가·정정과 관심 해제를 구분한다. 신규 진입 분석의 NO_TRADE를 보유 매도 지시로 표시하지 않는다.

### 간단한 와이어프레임

```text
내 종목 관리
관심 종목 {N}   [보유 종목 {M}]
------------------------------------------------------------
종목     수량    평균단가    평가손익    관리 상태
A종목    {값}    {값}        {값}        {기존 상태}
------------------------------------------------------------
A종목                         최근 확정 가격 {값} {기준일}
수량 {값}   평균단가 {값}   평가손익 {값}   실현손익 {값}

보유분 관리 기준                         적용일 {날짜}
손절 기준 {값}   1차 목표 {값}   2차 목표 {값}
현재 상태 {기존 판단과 짧은 이유}
[거래 기록 / 추가]               [신규 진입 관점으로 분석]

관련 뉴스 {소수의 제목 링크}
```

가격이 오래되면 “현재가”라는 표현을 피하고 기준 시각을 유지한다. 오래된 시세로 계산된 손익은 그대로 최신 손익처럼 강조하지 않는다. 거래가 남아 있는 종목을 단순 목록 삭제로 지우는 행동은 제안하지 않는다.

## D7 데이터와 시스템 상태

### 현재 문제

상단의 KRX·DART 중심 표시가 실제 KIS·NAVER NEWS의 역할과 일치하지 않는다. 공급자를 계속 추가하면 화면이 기술 정보로 복잡해진다.

### 사용자가 혼란스러운 이유

설정 여부, 마지막 연결 성공, 실제 데이터 최신성이 같은 “정상”으로 읽힐 수 있다. 사용하지 않는 선택 기능이 전체 서비스 장애처럼 보일 수도 있다.

### 개선 원칙

상단에는 사용 영향 요약 하나를 둔다. 예를 들어 “데이터 상태 정상”, “기업 정보 확인 필요”처럼 표시한다. 상세 패널에서는 source별 역할과 알려진 상태를 구분한다. KIS의 역할과 활성 여부는 실제 설정을 확인해 표시하며 선택적 비활성 상태를 오류로 분류하지 않는다.

### 권장 정보 순서

현재 사용 가능한 기능 → 영향을 받는 기능 → 마지막 확인 시각 → provider별 상세 → 사용자가 할 수 있는 해결 행동 순으로 둔다. Secret이나 인증 헤더를 표시하지 않는다.

### 권장 인터랙션

- 전역 “데이터 상태”를 누르면 오른쪽 패널을 연다. 모바일은 전체 화면으로 열고 닫으면 이전 위치로 복귀한다.
- KRX·DART·KIS·NAVER NEWS를 상세 목록에 포함한다. 역할은 시장·기업 정보·실제 KIS 사용 역할·기사 연결 등 사용 기능과 연결해 설명한다.
- 설정만 확인됐다면 “설정됨 · 연결 확인 전”으로 쓴다. 마지막 성공 시각이나 오류가 실제로 없으면 생성하지 않는다.
- 상태 재확인, 데이터 준비, 실제 제공되는 설정 경로만 행동으로 연결한다. 사용자 권한 밖의 장애에는 반복 재시도를 요구하지 않는다.

### 간단한 와이어프레임

```text
전역 상단                              [데이터 상태]

                                  데이터 상태       [닫기]
                                  ------------------------
                                  {사용 영향 요약}
                                  마지막 확인 {시각/미확인}

                                  KRX         {상태}
                                  시장 가격   데이터 {날짜}
                                  DART        {상태}
                                  기업 정보   데이터 {날짜}
                                  KIS         {활성/비활성}
                                  {실제 제공 역할}
                                  NAVER NEWS  {상태}
                                  기사 연결   조회 {시각}
                                  [상태 확인] [데이터 준비]
```

전체 상태는 현재 활성 기능에 미치는 영향을 기준으로 해석한다. 뉴스만 실패하면 시장 가격 전체를 사용 불가로 표시하지 않는다. 수집이 성공했어도 기준일이 오래되면 최신성 문제를 별도로 보여준다.

## D8 시장 데이터 준비와 진행

### 현재 문제

“시장 데이터 준비 시작” 이후 진행 화면으로 연결되지 않아 작업 상태와 완료 여부를 알 수 없다. 결과가 준비됐더라도 다음 행동이 명확하지 않다.

### 사용자가 혼란스러운 이유

시작 요청이 전달된 것과 실제 수집 중인 상태를 구분할 수 없다. 화면을 다시 누르면 중복 실행되는지, 다른 화면으로 가면 작업이 취소되는지도 알기 어렵다.

### 개선 원칙

준비 범위 확인 → 시작 요청 중 → 진행 → 완료 또는 실패 → 출발 목적에 맞는 행동을 한 흐름으로 구성한다. 독립된 진행 화면을 사용하고, 다른 화면에 있는 동안에도 진행 중임을 확인할 수 있는 진입점을 유지한다.

### 권장 정보 순서

무엇을 준비하는지와 범위 → 현재 상태 → 실제 관측된 진행량·최근 갱신 시각 → 실패·누락 항목 요약 → 가능한 행동 → 완료 후 복귀 순으로 둔다. 개발 로그 전체를 기본 화면에 노출하지 않는다.

### 권장 인터랙션

- 시작 즉시 진행 화면을 열고 요청 중과 실행 중을 구분한다. 시작 버튼을 다시 누르는 방식으로 상태를 확인하게 만들지 않는다.
- 전체량이 알려진 경우에만 완료량/전체량과 %를 표시한다. 전체량이 없으면 처리한 수와 현재 단계를 보여주고 가짜 백분율·예상 종료 시각을 만들지 않는다.
- 상태 응답이 끊기면 “진행 상태를 확인하지 못했습니다”로 표시한다. 작업 실패로 단정하지 않는다. 확인 행동은 새 작업 실행과 분리한다.
- 완료 시 출발 화면과 선택 종목·조건을 유지해 복귀한다. 부분 완료는 사용할 수 있는 범위와 누락 범위를 함께 보여준다.

### 간단한 와이어프레임

```text
시장 데이터 준비                        [출발 화면으로]
대상 {시장/종목}   기간 {시작~종료}
------------------------------------------------------------
{대기 / 준비 중 / 완료 / 일부 누락 / 실패 / 상태 미확인}

{완료 N / 전체 M}       {실제 계산 가능한 경우에만 %}
현재 단계 {실제 제공되는 단계}
최근 상태 갱신 {시각}

확인할 항목 {누락 또는 실패 요약}
[상태 다시 확인]                [제공되는 경우 상세 내역]
------------------------------------------------------------
완료 시  {준비된 범위와 결과}
[후보 찾기로 / 과거 성과로 / 출발 화면으로]
```

백그라운드 지속, 중단, 재개, 실패 항목만 재시도는 현재 기능이 지원하는 경우에만 노출한다. 지원 여부 확인 전에는 화면을 떠나도 계속된다고 약속하지 않는다. 이번 설계는 신규 작업 API나 저장 구조를 정의하지 않는다.

## E 관심 종목과 보유 종목의 구분

두 화면은 종목 식별과 데이터 기준을 공유하지만 첫 질문과 주요 행동이 다르다. 한 화면에서 열 몇 개만 바꾸는 수준에 그치지 않고, 상세 영역의 순서와 문구를 구분한다.

| 구분 | 관심 종목 | 보유 종목 |
| --- | --- | --- |
| 첫 질문 | 지금도 검토할 만한 상태인가 | 실제 보유 상태와 관리 기준은 무엇인가 |
| 목록 우선 정보 | 현재 판단, 가격, 마지막 분석 | 수량, 평균단가, 평가손익, 관리 상태 |
| 상세 첫 영역 | 현재 판단과 관찰 조건 | 실제 보유량·가격 기준일·평가 및 실현손익 |
| 가격 기준 | 관심 가격이 실제로 있으면 표시 | 적용된 손절·1차 목표·2차 목표 |
| 주요 행동 | 분석 보기 | 보유 관리 기준과 거래 기록 확인 |
| 등록 행동 | 관심 추가·해제 | 기존 거래 입력을 통한 보유 기록 |
| 뉴스 | 관찰 판단에 참고할 하단 정보 | 보유 관리에 참고할 하단 정보 |
| 상태 변화 | 비교 이력이 있는 범위에서 표시 | 기존 관리 상태와 적용된 기준을 표시 |
| 과거 성과 | 분석을 더 확인하는 선택적 경로 | 신규 진입 조건 검토 경로이며 원장 변경 없음 |
| 제거 의미 | 관심 상태 해제 | 관심 해제와 다름. 거래 삭제·정정은 기존 절차 |

### 공통으로 유지할 정보

종목명·코드·시장, 최근 확정 가격과 기준 시각, 관심·보유 상태, 마지막 분석 시각은 의미를 일관되게 유지한다. 두 화면의 같은 값이 기준일 차이 때문에 다르면 각 시점을 보여준다. 한쪽 화면의 값으로 다른 쪽의 실제 기록을 조용히 덮어쓰지 않는다.

### 함께 보유하거나 관찰하는 종목

한 종목에 두 상태가 모두 존재하면 관심 화면에는 보유 중임을 짧게 표시하고 “보유 관리 보기”를 제공한다. 보유 화면에서도 관심 상태를 확인할 수 있지만 손익보다 크게 강조하지 않는다. 목록별 개수와 전체 종목 수를 혼동하지 않도록 관심·보유 수를 각각 표시한다.

### 보유분 관리 기준의 구성

명칭은 “보유분 관리 기준”, 부연 문구는 필요할 때 “현재 보유분에 적용된 손절과 목표 가격”으로 쓴다. 기본 정보는 손절 기준, 1차 목표, 2차 목표, 적용 기준일, 현재 관리 상태다. 실제 적용 중인 기준과 새 분석이 제시한 기준을 같은 표 안에 섞지 않는다.

관리 기준이 하나면 단일 표로 표시한다. 여러 계획을 고르는 선택 UI를 만들지 않는다. 실제 적용 이력이 있을 때만 이력 보기를 제공한다. 미적용 상태에서는 없는 목표값을 0원으로 채우지 않는다.

## F 데이터 준비와 부족 상태

정상 화면보다 먼저 복구 동선을 확인한다. 상태 설명과 행동은 같은 영역에 두고, 경고 배너만 추가한 뒤 사용자가 메뉴를 찾아다니게 만들지 않는다.

| 상태 | 기본 표시 | 다음 행동과 제한 |
| --- | --- | --- |
| 시작 요청 중 | 데이터 준비 요청을 전달하고 있습니다 | 진행 화면 유지. 시작 중복 입력 방지 |
| 대기 또는 수집 중 | 현재 단계, 관측된 진행량, 마지막 갱신 | 상태 확인과 출발 화면 복귀. 지속·취소 안내는 실제 기능에 맞춤 |
| 정상 완료 | 준비된 대상과 기간, 완료 시각 | 후보 찾기 또는 원래 과거 검증으로 복귀 |
| 일부 누락으로 완료 | 사용할 수 있는 범위와 누락 항목 수 | 가능한 기능은 계속 사용. 누락 준비·재시도는 지원 범위에서 제공 |
| 명확한 작업 실패 | 실패한 범위와 확인된 이유 | 다시 시도 또는 설정 확인. 성공한 자료가 있으면 유지 |
| 상태 확인 불가 | 작업 상태를 확인하지 못했습니다. 마지막 확인 시각 | 상태 다시 확인. 작업을 새로 시작하거나 실패로 단정하지 않음 |

### 3년 검증 자료가 부족한 경우

첫 문장은 “3년 검증에 필요한 데이터가 부족합니다”로 둔다. 그 아래에 확보한 유효 거래일 수, 필요 수, 확보 기간을 표시한다. 이 값은 실제 검증 기준에서 가져오며 일률적으로 3년=특정 거래일 수라고 정하지 않는다.

부족 이유에 따라 행동을 달리한다. 아직 수집하지 않은 기간은 데이터 준비로 연결한다. 자료는 있지만 결측·품질 문제로 사용할 수 없는 경우에는 확인된 사유를 표시한다. 상장한 지 3년이 되지 않은 경우에는 전체 3년 자료를 만들 수 없다고 설명한다.

기존 계산이 지원하는 기간만 선택 가능하게 한다. 짧은 기간으로 실행한 결과에는 실제 기간을 명확히 표시한다. 실행할 수 있는 대안이 없으면 “종목 분석으로 돌아가기”를 제공하고, 이 검증을 마쳐야만 분석·관심 등록을 사용할 수 있는 것처럼 만들지 않는다.

### 진행 정보가 현재 제공되지 않는 경우

이번 UX 제안에 필요한 값과 현재 제공값을 구분해 후속 검토 목록에 남긴다. 전체량이 없으면 백분율을, 단계 정보가 없으면 구체적인 수집 단계를, 작업 지속성이 확인되지 않으면 백그라운드 실행 안내를 만들어 넣지 않는다.

상태값 미지원은 개발 단계에서 확인할 의존성이다. 이 문서에서 backend API나 DB를 새로 설계해 해결하지 않는다. 현재 확보 가능한 실제 상태만으로도 시작 요청 중·마지막 확인·확인 재시도·원래 화면 복귀는 의미가 구분되도록 설계한다.

## F 부분 데이터와 오류 상태

### 화면별 복구 계약

| 상태 | 사용자에게 보여줄 내용 | 다음 행동 |
| --- | --- | --- |
| 초기 로딩 | 어느 영역을 불러오는지 표시 | 뉴스·기업 정보의 지연으로 이미 확보한 가격을 가리지 않음 |
| 가격 데이터 오래됨 | 최근 확정 가격과 기준일 | 지원되는 가격 갱신 또는 데이터 준비. 최신 가격처럼 표기하지 않음 |
| DART 등 일부 오류 | 영향을 받은 기업 정보 영역에 한정해 안내 | 해당 영역 재조회 또는 데이터 상태 확인. 정상 가격·분석은 유지 |
| 뉴스 오류 | 최근 뉴스를 불러오지 못했습니다 | 뉴스 새로고침 또는 원문 목록 복귀. 전략 결과는 유지 |
| 뉴스 결과 없음 | 현재 조회된 뉴스가 없습니다 | 상태와 조회 시각 제공. 뉴스 없음으로 투자 판단을 생성하지 않음 |
| 필수 데이터 없음 | 실행 불가 이유와 부족 범위 | 데이터 준비 또는 정상 동작 가능한 출발 화면으로 복귀 |
| 빈 관심 목록 | 관심 등록한 종목이 없습니다 | 후보 찾기 또는 종목 검색 |
| 빈 보유 목록 | 등록된 보유 내역이 없습니다 | 실제 거래 기록을 입력하는 보유 등록 |

### 상태 전환과 화면 보존

```text
미준비 -> 준비 요청 -> 대기/진행 -> 완료 -> 출발 목적 계속
                           |         |
                           |         +-> 일부 누락 확인
                           +-> 실패 -> 가능한 복구 행동
                           +-> 상태 미확인 -> 상태 재확인

종목 변경 -> 새 종목 로딩 -> 사용 가능한 영역부터 표시
                         -> 실패한 영역에만 오류 안내
```

종목 A에서 B로 바꾸면 A의 뉴스·판단을 B의 제목 아래 잠깐 남겨두지 않는다. 입력값을 바꾸고 아직 다시 실행하지 않은 결과는 “이전 조건의 결과”로 표시한다. 오류를 해결한 뒤 사용자의 선택 종목·필터·검증 조건이 초기화되지 않게 하는 경험을 목표로 한다.

여러 provider 중 선택적으로 사용하지 않는 source는 “사용 안 함”으로 표시한다. 설정 누락과 연결 실패, 일시적인 요청 제한, 데이터 자체의 오래됨을 모두 “오류” 하나로 뭉치지 않는다. 다만 기본 화면에는 내부 오류 코드 대신 사용 영향과 가능한 행동을 먼저 보여준다.

### 접근성과 피드백

진행·완료·실패는 색만으로 구분하지 않는다. 상태 변경을 보조 기술에서도 인지할 수 있게 하고, 화면 이동 후 제목이나 상태 요약에 초점이 자연스럽게 이어지도록 설계한다. 지속적인 갱신마다 사용자의 읽기 위치를 강제로 옮기지 않는다. 성공 안내는 사라지는 알림만으로 끝내지 않고 완료 상태와 다음 행동을 화면에 남긴다.

## G 문장과 정보 표현 가이드

### 기본 작성 규칙

결론을 먼저 쓰고 핵심 이유는 1~2문장으로 제한한다. 다음 행동은 문장 속에 숨기지 않고 의미가 분명한 버튼 이름으로 표현한다. 계산 방법과 예외 설명은 필요한 상세 영역으로 이동한다. 한 문장에는 한 가지 판단만 담는다.

“쉽게 말해”, “좋은 소식이에요”, “따냈어요”처럼 가볍거나 가르치는 말투를 쓰지 않는다. 성인 사용자를 존중하는 간결한 설명체를 사용한다. 쉬운 표현으로 바꾸더라도 확정 사실·가능성·가상 조건·실제 원장의 구분은 유지한다.

### 현재 표현과 개선 예시

아래 현재 표현은 요청문에 제시된 명칭과 메시지를 기준으로 한다. 별도 예시로 표시한 행은 현행 화면의 정확한 문구를 인용한 것이 아니다.

| 현재 표현 또는 의미 | 개선 표현 | 함께 제공할 행동 |
| --- | --- | --- |
| 시작되었습니다 | 시장 데이터를 준비하고 있습니다 | 진행 상태 확인. 시작 후에는 진행 화면으로 연결 |
| 3년 검증 데이터 부족 | 3년 검증에 필요한 데이터가 부족합니다 | 확보 N개 / 필요 M개, 부족 이유, 가능한 준비 행동 |
| 신규 진입 판단 | 보유 종목에서는 신규 진입 관점 | 보유 관리 보기 |
| 현재 관리 계획 | 보유분 관리 기준 | 적용일과 손절·목표 기준 확인 |
| 종목 과거 성과 | 메뉴명은 유지. 선택한 조건의 과거 결과를 확인합니다 | 기존 결과 보기 또는 검증 실행 |
| 관심종목과 보유종목이 같은 의미로 보임 | 관심은 관찰 중인 종목, 보유는 실제 보유 내역 | 관심 등록과 거래 기록을 통한 보유 등록 구분 |
| NO_TRADE 코드가 그대로 보이는 경우 | 신규 진입 보류 | 판단 근거. 보유 종목에는 관리 화면 연결 |
| 예시 — 뉴스 전체 요청 실패 | 최근 뉴스를 불러오지 못했습니다 | 뉴스 새로고침 |
| 예시 — 최신 시세처럼 표시된 과거 가격 | 최근 확정 가격 · 기준일 {날짜} | 사용 가능한 갱신 경로 |

### 시각적 표현 규칙

Typography, 구분선, 표, 편집된 정보 순서로 화면을 구성한다. 제목·결론·본문·보조 정보의 크기와 대비를 구분하고 모든 영역을 둥근 카드로 감싸지 않는다. 주요 행동은 화면마다 하나를 우선하며 보조 행동은 텍스트 버튼으로 구분한다.

색은 손익, 실제 상태 변화, 중요한 오류 등 의미가 있는 정보에 제한한다. 색만으로 상태를 전달하지 않는다. 뉴스 제목에 긍정·부정 색이나 배지를 붙이지 않는다. Dark와 Low-Glare Light는 동일한 정보 구조와 대비 기준을 유지하고 Light에서 큰 순백색 면이나 눈부신 강조색을 피한다.

최대 폭과 좌측 정렬 기준을 페이지별로 일관되게 유지한다. 표가 좁은 화면에 맞지 않으면 핵심 열을 우선하거나 표 영역 안에서 가로 스크롤한다. 페이지 전체를 가로로 밀어내지 않는다. 펼쳐보기는 보조 설명에만 사용하며 다음 행동에 필요한 오류·기준일·실제 보유 상태는 기본 화면에 남긴다.

## H 구현 검토 우선순위

아래 순서는 후속 소스 비교와 개발 명세 전환을 위한 우선순위다. 이번 단계에서 코드·계산·DB·API를 수정하지 않는다. 새 투자 전략, 추천 알고리즘, 자동 매매, 임의의 뉴스 투자 판단은 범위에 포함하지 않는다.

| 우선순위 | 검토할 변경 | 해결할 문제 |
| --- | --- | --- |
| P0 | 데이터 준비 시작 후 진행 화면, 상태 확인, 완료 후 복귀 | 작업이 실제로 진행되는지 알 수 없는 단절 |
| P0 | 일반 데이터 부족과 3년 검증 부족의 원인·행동 연결 | 경고 이후 아무 행동도 할 수 없는 상태 |
| P0 | 뉴스·provider 부분 오류 격리와 종목 전환 상태 | 정상 결과 소실과 다른 종목 정보의 혼재 |
| P0 | 가상 분석 입력과 실제 원장 기록의 경계 표시 | 실제 보유 정보를 잘못 이해하거나 기록할 위험 |
| P1 | 보유 중인 종목의 신규 진입 관점 및 보유 관리 연결 | 신규 진입 보류를 매도 판단으로 읽는 혼란 |
| P1 | 관심·보유 상세 분리와 보유분 관리 기준 명칭 | 서로 다른 관리 목적과 적용 상태의 혼재 |
| P1 | 과거 성과의 목적과 기존 결과 재사용 경험 | 매번 검증해야 하는지 모르는 문제 |
| P1 | 뉴스 영역 축소와 NEWS.2 관련성 설명 자리 | 분석보다 뉴스가 커지는 문제와 향후 확장 |
| P1 | 결론·이유·행동 중심의 문구, 통합 데이터 상태 | 긴 설명과 기술 상태를 사용자가 해석하는 부담 |
| P2 | 콘텐츠 폭·정렬선·간격, 미니 차트와 양 테마 | 시장 흐름 파악과 화면 일관성의 부족 |

### 사람과 설계자가 먼저 확인할 질문

- 시장 데이터 준비를 시작한 뒤 별도 설명 없이 현재 상태와 다음 행동을 찾을 수 있는가?
- 보유 종목을 분석해도 현재 보유분의 매도 판단으로 오해하지 않는가?
- 관심 화면과 보유 화면을 보고 각각 무엇을 해야 하는지 즉시 구분되는가?
- 3년 자료 부족이 수집 누락인지 상장 기간 문제인지 알 수 있고, 가능한 행동으로 이어지는가?
- 뉴스가 종목 분석의 결론보다 앞서 보이지 않으면서 원문을 쉽게 확인할 수 있는가?
- 과거 성과와 성과 추적의 역할이 구분되며 검증을 매번 해야 한다는 부담이 없는가?

### 후속 소스 비교에서 확인할 의존성

실제 진행량과 단계·작업 지속성, 실패 후 복구 범위, 데이터 부족 이유와 유효 거래일 수, 기존 검증 결과 재사용, 관심 가격·상태 변화 기록, 적용된 보유 기준의 상태값, provider별 설정·연결·최신성 정보를 확인한다. 없는 값을 UI에서 만들어 넣지 않는다. 새 backend 기능이 필요한 항목은 이번 UX 변경과 분리해 의사결정 대상으로 남긴다.

검토가 끝나면 승인된 화면 구조를 실제 소스와 대조해 개발 명세로 변환한다. 종목 성과 추적은 그 과정에서도 별도 개편 전까지 대규모 구조 변경을 보류한다.
