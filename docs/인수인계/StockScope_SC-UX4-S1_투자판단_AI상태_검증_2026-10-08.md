# SC-UX4-S1 — Scanner 판단 문구와 미충족 조건·AI 기능 상태

기준: 2026-10-08 · 선행 작업 SC-UX3 / main fef69d2
변경 범위: 프론트엔드 설명문, 조건 근거 UI, Jev 기능 제공 상태 표시만. **기존 Scanner 선정·정렬·전략·Risk 계산, DB, 외부 Jev 실행, Runtime 전송은 변경하지 않음.**

## 왜 수정했나

기존 1위 READY는 기본 전략 조건이 모두 충족돼도 '지금 매수하라는 뜻이 아니다'만 반복했다. NEAR_READY는 missing 개수만 보여줘 무엇이 부족한지 첫 화면에서 보이지 않았다. 일부 문구는 9개 중 8개 충족을 8개 중 9개로 잘못 표현했다. AI 기능은 서버 `available=false`인데 브라우저 저장값 ON이 실제 동작하는 스위치처럼 보였다.

## 새 표시 규칙

- READY + 위험 차단 없음 + 분석일 참고 가격 범위 내: **분석일 기준 진입 조건 충족**. 새로운 KIS 시세나 전략 재평가가 없는 상태에서 '지금 매수 가능'으로 승격 금지.
- 참고 가격 범위 밖: **분석 당시 가격 조건 이탈**은 전략 조건 충족 상태와 별개로 표시.
- NEAR_READY/WAIT 등: `conditions.missing`와 `top_missing` 첫 항목의 **실제 label/current_value/required_value/detail** 표시. 입력 값이 비거나 리스트가 대표 항목만 담은 경우 전체 조건인 것처럼 꾸미지 않음.
- RISK_HOLD/RISK_BLOCKED 및 risk.warning: 부족 조건·가격보다 **위험 차단 이유를 우선** 표시. 조건 자체는 숨기지 않음.
- 총 조건 수가 0/불일치: 계산 자료 부족. 충족으로 추정 금지.
- AI API loading/failure/unavailable/active는 서로 구별. 서버 미제공 시 컨트롤 비활성, **AI 검토 미제공** 표시. 저장된 사용자 토글 설정 값은 삭제하거나 강제로 덮어쓰지 않음.
- 기존 TypeSafe Jev 실제 모델 호출은 비활성 유지. 사용자에게 제공하는 READY/NEAR_READY는 **Jev가 만든 판단이 아님**.

## 사용자 검증해야 할 내용

1. READY 6/6 예시(89,400원, ABOVE 88,200원)의 요약: 분석일 진입 조건 충족, 실시간 유효성 확인 전.
2. NEAR_READY 8/9: 실제 빠진 조건명과 현재/필요 값이 목록과 선택 종목 요약에 표시되는지 확인.
3. 종목 변경 후 이전 종목 조건이 남지 않는지 확인.
4. AI 비활성일 때 상단 'AI 검토 미제공'과 비활성 컨트롤, 요약/AI 탭 상태가 일치하는지 확인.
5. 1440x900 PC에서 후보 목록·핵심 판단이 보이고, 모바일에서 조건값이 잘리지 않는지 확인.
6. 기존 관심/보유 등록, X2 비교, 과거 데이터 준비, 수동 KIS 시세 조회 동작 보호.

위 동작은 코드 및 자동 테스트로 우선 검증하며, 현재 PC 브라우저 스크린샷/실제 응답 데이터의 UAT는 별도 확인해야 한다.

## 남은 범위

- JEV-ACT1 실제 TypeSafe Provider 모델 호출 활성화/응답 유효성/효용 비교: **미착수**. 기본 전략·Risk 판단과 결합하지 않음.
- 최신 KIS 시세 기반 전략·Risk 재평가: **별도 설계**. 가격 조회만으로 READY를 현재 매수 가능으로 승격 금지.
- 다른 PC Runtime 동기화: **계속 보류**.
