# StockScope v0.19.6 — Risk Policy Decision

## 목적

v0.19.5에서 한 종목의 동일 신호를 대상으로 아래 Risk 정책을 비교했다.

- 현재 방식: CAUTION도 진입
- CAUTION 전체 제외
- 과도한 손절만 제외: 기존 Risk Engine 경고 기준인 손절거리 12% 이상
- 더 가까운 유효 지지 사용: 주요 지지와 MA20 중 진입가에 더 가까운 유효 지지를 연구용으로 사용

v0.19.6의 목적은 **한 종목에서 좋아 보인 정책을 바로 실제 규칙으로 채택하지 않고**, 동일 시장의 여러 종목에서도 문제 감소가 반복되는지 자동으로 교차검증하는 것이다.

## 사용자 흐름

1. 기존 눌림목 백테스트를 실행한다.
2. Risk 정책 비교에서 한 종목 기준 후보를 확인한다.
3. `대표 종목으로 자동 검증`을 누른다.
4. StockScope가 동일 시장에서 대표 표본을 자동 선택한다.
5. 동일 기간·동일 비용·동일 보유기간으로 네 Risk 정책을 각 종목에 다시 적용한다.
6. StockScope가 반복성, 문제 감소, 거래 유지, MDD/거래당 평균의 동시 악화 여부를 평가한다.
7. 충분히 반복되면 `정책 승격 검토 후보`, 아니면 `정책 변경 보류`로 설명한다.

사용자는 종목을 하나씩 직접 선택하거나 숫자를 보고 정책을 직접 고를 필요가 없다.

## 대표 종목 자동 선택

- 기준 종목과 **같은 시장(KOSPI 또는 KOSDAQ)** 안에서 선택한다.
- 검증 시작일 이전 최대 15일에서 가장 가까운 KRX 거래일 스냅샷을 사용한다.
- 시작 시점에 실제 존재했던 종목만 사용해 미래 시점의 종목 선택 편향을 줄인다.
- 시가총액 순으로 정렬한 뒤 상위·중상위·중간·중하위·하위 구간에서 5개를 자동 선택한다.
- 자동 표본에서는 스팩과 우선주 계열을 제외해 특수한 가격/유동성 구조가 표본을 흔드는 것을 줄인다.
- 기준 종목 1개 + 자동 표본 5개, 최대 6개를 검증한다.
- 거래가 없거나 데이터가 부족한 종목은 결과에 명시하고 정책 근거에서 제외한다.

이 방식은 업종 대표 표본이나 완전한 통계 표본을 뜻하지 않는다. v0.19.6은 Risk 정책의 **반복 가능성을 빠르게 선별하는 연구 단계**다.

## 정책 판정 원칙

수익률이 가장 높은 정책을 자동 선택하지 않는다.

각 정책에 대해 다음을 구분한다.

- `triggered_stocks`: 정책 때문에 실제 거래 또는 손절 기준이 바뀐 종목 수
- `problem_solved_stocks`: 정책이 겨냥한 위험 문제가 실제로 줄어든 종목 수
- `balanced_improvement_stocks`: 위험 문제를 줄이면서 거래당 평균과 최대 낙폭이 둘 다 악화되지 않은 종목 수
- `harmed_stocks`: 거래당 평균과 최대 낙폭이 둘 다 악화된 종목 수
- `overfiltered_stocks`: 기존 거래의 절반 미만만 남긴 종목 수
- `average_trade_retention_pct`: 정책 적용 후 평균 거래 유지율
- `average_expectancy_delta_pctp`: 거래당 평균 변화
- `average_max_drawdown_delta_pctp`: 최대 낙폭 변화

### 재사용한 가드레일

v0.19.5에서 이미 `거래의 절반 미만 유지`를 지나치게 강한 필터로 해석하고 있으므로, v0.19.6도 동일한 50% 기준을 재사용한다. 결과를 보고 새 임계값을 맞추지 않는다.

### 여러 종목 반복 판정

- 실제 거래 표본이 있는 종목이 3개 미만이면 `표본 부족`
- 정책이 실제로 결과를 바꾼 종목이 2개 미만이면 `반복되지 않음`
- 작동한 종목의 절반 이상에서 기존 거래의 절반 이상이 사라지면 `너무 강한 필터`
- 작동한 종목의 절반 이상에서 목표 문제가 줄고, 거래당 평균과 MDD가 함께 악화되지 않으면 `반복 개선 확인`
- 위험은 반복적으로 줄지만 성과/거래기회 대가가 남으면 `위험 개선·대가 있음`
- 종목별 방향이 다르면 `결과 혼재`

`반복 개선 확인`이 된 정책만 `정책 승격 검토 후보`가 될 수 있다. 실제 Risk Engine은 자동 변경하지 않는다.

## 백테스트 성능 영향

자동 교차검증은 같은 시장 종목을 사용한다. KRX 일별 종목 API는 날짜별 시장 전체 데이터를 내려주고 기존 StockScope는 해당 원본을 gzip 캐시하므로, 기준 종목 백테스트가 이미 끝났다면 같은 시장의 다른 종목 검증에서 기존 날짜 캐시를 크게 재사용할 수 있다.

교차검증은 별도 Job으로 실행하며 진행 중 현재 종목과 내부 진행률을 표시하고 취소할 수 있다. 기본 백테스트를 다시 실행하거나 결과 화면을 강제로 이동시키지 않는다.

## UX

v0.19.5의 한 종목 정책 비교 표는 기본 접힘 상태로 내린다. 기본 화면에는 다음 순서만 우선 노출한다.

1. 한 종목에서 발견한 정책 후보
2. `대표 종목으로 자동 검증`
3. 여러 종목 교차검증 결론
4. 가장 유력한 후보 또는 `Risk 규칙 변경 보류`
5. 정책별 반복성 요약
6. 종목별 상세 숫자는 접힌 근거 영역

## 실제 규칙 변경 여부

v0.19.6에서는 아래를 변경하지 않는다.

- CAUTION 실제 진입 차단
- 손절거리 12% 실제 하드 게이트
- 주요 지지/MA20의 실제 Risk Engine 우선순위
- 눌림목 진입 조건
- Strategy Score 계산식

여러 종목에서 반복 개선이 확인돼도 이번 버전은 `정책 승격 검토 후보`까지만 만든다. 다음 단계에서 다른 기간 또는 다른 시장으로 검증한 뒤 실제 Risk Gate 반영 여부를 결정한다.

## API

`POST /api/backtest/pullback/risk-policy-validation/jobs`

기존 `PullbackBacktestRequest`와 같은 설정을 받는다. 종목 목록은 받지 않는다. 서버가 자동으로 표본을 선택한다.

진행/취소는 기존 Job API를 재사용한다.

- `GET /api/backtest/jobs/{job_id}`
- `DELETE /api/backtest/jobs/{job_id}`

## 검증

- 신규 교차검증 단위 테스트 6개 통과
  - 여러 종목에서 반복된 좁은 정책을 우선하는지
  - 한 종목만 좋아진 정책을 승격하지 않는지
  - 자동 종목 선택이 결정적이고 시총 구간을 넓게 포함하는지
  - 실제 Risk 규칙을 자동 변경하지 않는지
  - 사용자가 종목 목록을 주지 않아도 서비스가 자동 선택·검증하는지
  - 자동 표본에서 스팩/우선주 계열을 제외하는지
- 변경 Python 파일 `py_compile` 통과
- 변경 TS/TSX 파일은 임시 React 타입 선언을 사용한 `tsc --noEmit` 검사 통과

전체 프로젝트 의존성이 이 작업 컨테이너에 완전히 재구성되어 있지 않아 전체 백엔드 테스트 스위트와 실제 Vite production build는 이번 환경에서 실행하지 못했다.
