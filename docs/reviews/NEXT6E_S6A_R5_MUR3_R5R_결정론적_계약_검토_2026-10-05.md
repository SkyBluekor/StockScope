## 9. Finding MUR3-F01 — Missing-horizon semantics

Severity:

```text
MAJOR
```

Status:

```text
UNRESOLVED
```

The method contract currently states:

```text
joint_eligibility:
row included only when all required horizons
1/5/10 are AVAILABLE and valid
```

This naturally implies:

```text
row with one missing horizon
→
exclude before constructing joint chronology
```

But the same contract also states:

```text
missing_required_horizon
=
INVALID_INPUT_DO_NOT_IMPUTE
```

which naturally implies:

```text
row with one missing horizon
→
input invalid / fail-close
```

These semantics are not equivalent.

They change:

```text
joint n
window length
anchor mapping
all downstream metrics
common-N
```

Therefore an implementation cannot choose either interpretation independently.

Required BR1 decision:

```text
STRICT_COMPLETE_DATASET
or
PREDEFINED_JOINT_ELIGIBILITY_FILTER
```

must be frozen explicitly.

No choice is made by MUR3.

## 11. Finding MUR3-F03 — Numeric comparison canonicalization

Severity:

```text
MAJOR
```

Status:

```text
UNRESOLVED
```

R5R metrics can naturally be rational:

```text
T_EMP
=
k/w

median
=
integer or half-integer

MAD
=
integer or half-integer

L_EMP / S_EMP
=
general rational
```

Support status uses:

```text
metric <= tau
```

but the contract does not specify the canonical numeric representation / comparison rule.

Example:

```text
exact metric
=
1/3
```

If policy is represented as:

```text
0.333333
```

versus an exact rational or exact decimal contract, boundary status may differ.

This can change:

```text
SUPPORTED_WITHIN_POLICY
vs
EXCEEDS_POLICY
```

and therefore common-N.

Required BR1 resolution should define one canonical comparison model, for example:

```text
exact rational metric arithmetic
+
policy value represented as exact decimal/rational
+
cross-multiplication comparison without binary-float tolerance
```

or another equally explicit rule.

MUR3 does not choose the final rule.
