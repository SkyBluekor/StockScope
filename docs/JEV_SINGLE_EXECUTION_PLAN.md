## 1. 왜 기존 개발을 중단하고 정리하는가

사용자 목표는 **Scanner의 실제 종목 1개를 선택하여 TypeSafe JEV의 검증된 제2 의견을 받아보고, 기존 로컬 판단과 비교하는 간결한 프로그램**이다. 과거 작업에서는 진단기·공시 조회·합성 파이프라인과 UI 설명이 계속 늘었지만 사용자가 이 흐름을 재현하지 못했다.

### 확정된 사실(2026-10-30)

- `TypeSafeSystemOneProvider`, 실제 HTTP 요청/응답 유효성 검사, 사용자 환경의 **합성 입력에 대한 실제 유료 TypeSafe 호출 1회 성공** 기록은 이미 존재한다. 이 기능을 다시 만든다거나 새로운 canary를 반복하지 않는다.
- 실제 Scanner SHORT 정본 `a1e9c341-7542-4511-8740-e07f4ee250ff`의 ENTRY 후보 7개는 P5에서 `LOCAL_MATCH`; **기존 V4 로컬 의미 잔여 충돌 후보 0개**. 이를 임의로 JEV 호출 필요 후보로 바꾸지 않는다.
- V5 `event_v5.py`는 합성 `FAKE-JEV-EVENT-V5` 실행만 지원. 실제 외부 전송은 기본 차단되어 있고 공시·뉴스의 권한 없는 전송은 불가.
- 사용자 Windows에서 동국제약(086450) OpenDART 공시 **2건 실조회 성공**. P6-F에서 EventEvidence 형식 정규화 후보 2건을 표시했지만 **실제 DB 영구 저장·실종목 JEV 검토는 0건**이었다.
- `ScannerAiReview.tsx`가 489줄까지 커졌고, Mock·P6 진단·HOLD 메시지가 사용자 화면에 반복된다. **현재 UI를 계속 확장하는 방향은 중지**한다.
- OpenDART/Naver/KRX에서 파생된 실제 입력의 TypeSafe 전송 사용권은 현재 코드와 사용자 계정 증거만으로 확인되지 않았다. 사용자 체크박스나 프롬프트 재작성으로 우회 불가.

## 2. 제품 목표와 최종 인수 기준

### 사용자에게 보여줄 **단일 최소 화면**

- 선택한 **실제 종목**(이름, 코드)
- **기존 Scanner 판단**(사용자 프로그램에서 확인한 실제 값)
- **JEV 제2 의견**: 검토 전 / 실행 중 / 추가 확인 필요 / 추가 확인 필요성 낮음 / 판단 보류 / 실행 불가
- 실제 실행 결과가 있을 때만 **모델 식별·검토 시각·사용량/비용 확인 경로**
- **[JEV 검토 실행]** 버튼 하나 (입력권한·사용자 승인 조건 충족 시만 활성)

상세 기술 정보는 **관리자/개발자 진단 영역**으로 옮기며 기본 화면에서 보이지 않는다. 기존 결과, 원본 해시, 권리 게이트 기록은 백엔드에서 그대로 보존한다. 첫 화면에는 Mock, V4/V5, SourceRef, quality_hash, HOLD 계약명, 수집 파이프라인 단계를 노출하지 않는다.

### 최종 완료의 정의 — 모두 필요

1. Windows 실제 프로그램에서 실종목 **한 건**을 선택하고, **허용된 진짜 사용자 작성/보유 분석 입력**으로 검토를 요청한다. 실제 시장 출처의 권한 없는 숫자/뉴스/공시 파생물을 전송하지 않는다.
2. Fake가 아닌 `TypeSafeSystemOneProvider`가 **명시적 1회 실행 승인**을 받아 실제 네트워크 호출하고, 반환된 모델 ID/질문/응답을 검증한다.
3. 응답이 `PASS_THROUGH / REVIEW_REQUIRED / ABSTAIN` 중 하나로 **실제 종목·원본 입력·시간**에 연결되어 저장·재조회된다. 모델이 제공하지 않은 자연어 설명은 만들어내지 않는다.
4. 같은 요청의 새로고침·중복 클릭은 **중복 결제하지 않는다**. API 실패 때 Scanner·Holdings 원본 결과는 변하지 않는다.
5. 화면은 최소 구조로 정리되고, 사용자가 **기존 판단과 JEV의 차이**를 바로 확인할 수 있다.
6. CI 통과 외에 **실제 사용자 Windows 결과**가 증명된다. 성공하지 못한 단계는 완료로 표시하지 않는다.

**제품 한계:** 실제 종목을 선택했다는 사실만으로 모델이 그 종목의 실시간 시장 상황을 알고 있다는 뜻은 아니다. 최초 실사용의 JEV 입력은 사용자가 직접 작성·권리를 보유한 전략/관찰 등, 적법하게 전송 가능한 사실에 한정한다. 자동 시장·공시 문맥까지 포함한 모델 검토는 출처별 권한 확인 이후 별도 사용자 승인 없이는 확대하지 않는다. 사용자 작성 입력만으로 유용한 판단이 안 나오면 그 한계를 명시적으로 실패/제약으로 기록한다.

### 변경이 필요한 예외

해당 단계의 인수 테스트를 막는 **직접적인 버그**만 최소 범위 수정 가능. 기타 요청은 본 문서 `보류 목록`에 한 줄로 추가하고 **현재 단계에 구현하지 않는다**. 새로운 작업을 넣거나 완료 기준을 바꾸려면 사용자에게 변경 이유·예상 영향·기존 작업에서 빠지는 것을 먼저 명확히 설명하고 승인을 받는다.

### A. 사용자 AI 검토 UI 정리 (첫 구현 작업)

**목표:** 현재 선택 종목에 대한 AI 검토 영역에서 사용자에게 필요한 항목만 남긴다.

**허용 변경:** `frontend/src/components/ScannerAiReview.tsx` 및 재사용 가능한 최소 하위 컴포넌트, 관련 CSS/Playwright. 백엔드 서비스/계약/데이터 모델 수정 금지.

**정확한 작업:**
1. 사용자 기본 영역: 종목/기존 Scanner 판단/JEV 현재 상태/실제 실행 버튼(기존 차단 시 비활성)/실제 결과가 있는 경우의 메타정보.
2. `JevSyntheticDemo`, `JevEventV5Demo`, P6-A~F 디버그·조회·해시·중복 HOLD 및 공시 목록은 **일반 사용자 화면에서 감추고 개발자 진단에만 둔다**. 로직이나 원본 기록은 삭제하지 않는다.
3. 정상/미실행/권한 미확인/실패 시 일반 사용자 문구는 **한 번만** 보여준다. UI 중복과 불필요한 네트워크 조회가 늘어나지 않게 한다.
4. 작은 폭, 종목 변경, API 조회 실패, 저장된 기존 실모델 결과, 비활성 버튼 확인.

**A 통과:** 스크린샷에서 본문 요약이 간결하고, 기존 Scanner 및 보유 관리 UI 회귀 없음. CI+사용자 Windows 확인. **JEV 실제 호출 성공으로 보고하지 않는다.**

### B. 실제 TypeSafe 수동 검토 1건 (핵심 기능)

**목표:** 기존 HTTP 클라이언트를 선택한 실제 종목의 **전송권한이 확보된 사용자 작성 입력**에 연결한다. 원천/시점/실행 승인 조건이 안 되면 명확한 차단 이유를 보여주고 **가짜 성공**으로 완료 선언하지 않는다.

**허용 변경:** 기존 `backend/app/jev/typesafe_provider.py`의 TypeSafeSystemOneProvider, `review_service.py`/API/카탈로그/문서화된 계약을 **가능한 그대로 재사용**. 필요 최소한의 적법 입력 projection 및 사용자 실행 경계만 추가. 새 provider 구현 금지.

**실행 경로:**
1. 실제 선택 종목+저장된 Scanner 캡처 원본 ID 고정; 기존 로컬 분석은 읽기 전용.
2. 검토에 보낼 수 있는 입력의 출처·권리를 필드별 확정. 1차 경로는 **사용자가 직접 작성·권리를 보유한 전략 조건과 직접 관측한 사실**(현재 프로그램에 이미 있으면 재사용; 없을 때만 간결한 최소 입력 수단). Naver/DART 원문, KRX 유래·권한 미확인 시세/판정 등은 제외. 실자료 문구를 문장만 바꾼 파생본도 허용하지 않는다.
3. 모델이 대답할 수 있는 단일 검토 질문을 확정하고 입력·버전·실제 HTTP body hash를 남긴다. *실제 종목의 시장 적합성*을 판정할 충분한 적법 사실이 없으면 그럴듯한 투자 조언을 만들지 않는다.
4. 검증된 모델 ID, 질문 ID, 사용량·비용 불명 여부, API 실패·중복을 처리. 사용자가 **해당 실행에 대한 유료 호출 1회**를 명시적으로 승인해야만 네트워크 호출.
5. 해당 후보/입력/시점에만 유효한 결과 저장·재조회. 재시도는 자동으로 하지 않는다. 출력 타입은 `PASS_THROUGH/REVIEW_REQUIRED/ABSTAIN` 중 실제 검증된 값만.
6. 기존 코드에서 구현된 유료 합성 호출 성공을 재사용해 제공자 연결만 활용하고, **또 다른 합성 유료 canary를 수행하지 않는다**.
7. Fake/CI 테스트는 필요한 최소 계약 회귀에만 쓰고, 실제 외부 API 호출은 사용자 동의하에 Windows에서 1회 수행.

**B 통과:** 사용자 Windows에서 실제 선택 종목에 연결된 비합성·허용 입력으로 실제 TypeSafe 응답이 표시되고 결과 ID/입력해시/모델/시간·비용이 확인됨. 불충분한 적법 입력의 경우 **진입 장벽과 사용자에게 필요한 정확한 한 가지 조치**를 보고하고 B를 미완료로 유지. 새 Mock/수집 기능으로 우회하지 않는다.

### C. 유용성·범위 판단 (새 기능 아님)

**목표:** 실제 모델을 쓰는 가치가 있는지 데이터로 판단한다. 모델 확률을 수익률 확률로 해석하지 않는다.

1. 확인된 동일 입력에서 로컬 판단 / JEV 판정 / ABSTAIN / 실제 추가 검토 가치를 나란히 기록.
2. 왜 모델 검토가 필요한지 로컬 조건에서 설명 가능하면 해당 사유와 결과를 구분. 모델이 자연어 이유를 제공하지 않으면 이유를 생성하지 않는다.
3. 실제 비용·지연·실패·재요청 억제 확인. 최소 1회 유효 결과가 있으면 사용자에게 표시, 더 많은 사례는 별도 사용자 동의와 입력권한 확보 시에만.
4. 결과가 중복이거나 무용하면 **JEV 기능을 유지할지 수정/중단할지 제안**. 실거래 성과 향상이라고 주장하지 않는다.

**C 통과:** 한 페이지 이하의 실제 사용성 판단서(기존 분석 대비 차이/효과/비용/미확정)와 유지·수정·보류 결론. 그 다음 확장은 자동 승인하지 않는다.

## 6. 단계별 작업 보고 형식 (고정)

모든 완료/중단 보고는 다음 여섯 항목만 간단히 작성한다.

1. **이번 단계:** A/B/C 중 무엇인지
2. **변경 파일:** 무엇을 왜 바꿨는지
3. **실제 동작:** 합성/실종목/실모델을 정확히 구분
4. **검증:** CI 링크 + 사용자 Windows UAT 여부
5. **남은 장애:** 구체적 재현 증거 1~3개
6. **다음 작업:** 본 문서의 다음 단계만 명시

진행 상황은 **이 문서의 아래 진행표 한 군데만** 갱신한다. 다른 핸드오프 문서를 일회성으로 계속 추가하지 않는다. GitHub 커밋 한 건이 '기능 완료'의 증거는 아니다.

### 진행표

| 단계 | 상태 | 코드 커밋 | CI | 사용자 Windows UAT | 다음 |
|---|---|---|---|---|---|
| A | NOT_STARTED | — | — | — | AI 검토 UI 간소화 |
| B | NOT_STARTED | — | — | — | 비합성·허용 입력을 TypeSafe 1건에 연결 |
| C | NOT_STARTED | — | — | — | 실제 결과 실용성 비교 |

## 7. 보류 목록 (현 단계에 구현 금지)

- **공시 이벤트 영구 적재/자동 수집:** P6-E/F 코드와 약관 조사 결과만 보존. 별도 허용권 증빙 후 사용자 승인 전까지 시작하지 않음.
- **배치/자동 JEV:** 1건 수동 실사용의 효용 확인 전까지 금지.
- **신규 이벤트 분석 모델/정책·새 데이터 제공업체:** 현재 목표 밖.
- **UI의 추가 진단기·Mock 전시:** 일반 화면에는 표시하지 않음.

## 8. 다음 채팅의 고정 지시

> GitHub의 `docs/JEV_SINGLE_EXECUTION_PLAN.md`를 먼저 읽는다. 사용자 승인 전에는 코드 작업을 시작하지 않는다. 승인 후 현재 진행표에서 가장 이른 미완료 단계 **A**만 구현하고, 기존 Scanner/파생권한/TypeSafe 계약을 보존한다. '추가로 할 수 있는 기능'을 스스로 기획하지 않는다. A의 CI 및 Windows UAT 완료 후 사용자가 진행을 지시하면 B로 이동한다. 이 문서만 진행 상태를 갱신하며 새 장문의 기획 문서를 추가하지 않는다.
