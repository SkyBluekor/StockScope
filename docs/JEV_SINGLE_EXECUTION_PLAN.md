## 최종 제품 목표

실제 Scanner에서 종목 하나를 선택하고 **기존 로컬 판단과 검증된 TypeSafe JEV 제2 의견을 간결하게 비교**한다. 모델 응답이 실제 검토인지, 단지 로컬 분석인지 명확히 구분한다. 종목 가격·공시·뉴스 등 제3자 이용권이 미확인된 데이터는 외부 모델에 전송하지 않는다.

### 최종 인수 조건

1. 실제 종목과 그 Scanner 원본/분석시점이 그대로 고정된다.
2. 전송권리가 확인된 **사용자가 작성하거나 권리를 보유한 최소 입력**만 포함하고, 사용자는 유료 호출 전에 해당 요청을 명시적으로 승인한다.
3. 기존 `TypeSafeSystemOneProvider`로 **Fake가 아닌 실제 검토 1회**를 실행하여 응답을 모델 ID·입력 해시·시각·결과 ID와 함께 검증·저장·재조회한다.
4. 새로고침/중복 클릭으로 유료 요청이 중복 실행되지 않는다. 오류 시 Scanner의 기존 순위·Risk·보유/매매 내용 불변.
5. 사용자 화면에서 **Scanner 판단 / JEV 상태 또는 결과 / 실행 버튼**을 즉시 확인할 수 있다. 기술적 진단은 명시적으로 펼쳐야 보인다.
6. 코드 CI와 **사용자 Windows 실제 실행**을 모두 확인한다. 모델 결과가 유용하지 않으면 유용하지 않다고 기록한다.

최초 실모델 호출의 사용자 입력만으로 투자적합성을 단정하거나 모델의 의미 없는 숫자 출력을 투자 승률로 해석하지 않는다.

### B. 실제 종목 TypeSafe JEV 수동 검토 1건

**현재: NOT_STARTED.**

1. **현재 브랜치**에 있는 `TypeSafeSystemOneProvider`, 기존 서비스·API·모델 식별/응답 검증 로직을 먼저 살펴서 재사용한다. 다른 브랜치의 코드를 통째로 옮기지 않는다.
2. Scanner의 **실제 선택 종목, 캡처 ID, 시각**과 안전한 사용자 작성 입력을 연결한다. 이 입력만으로 검토 가능한 한 가지 질문을 확정한다. Naver/DART/KRX 원본·허용되지 않은 파생물 전송 금지.

6. UI는 A의 짧은 구조를 유지한다. 실제 응답이 있을 때만 판정·추가 확인 코드/검토시각 등을 표시하고, 기술 로그는 펼친 영역에 둔다.
